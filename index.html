// 02 — Fundamentos

Toda segurança se apoia em três pilares

A tríade CIA define o que proteger, contra quem e em qual nível.

C

Confidencialidade

Apenas pessoas autorizadas acessam a informação. Criptografia, autenticação forte e controle de acesso.

criptografia · ACL · MFA
I

Integridade

Os dados não foram alterados de forma indevida. Hashes, assinaturas e logs de auditoria.

hash · assinatura · auditoria
A

Disponibilidade

Sistemas e dados acessíveis quando necessário. Redundância, backups e mitigação de DDoS.

redundância · backup · DDoS
Você é o elo mais forte. Tecnologia defende sistemas, mas o fator humano decide entre um clique seguro e um incidente.
// 03 — O que te ataca

Suas possíveis ameaças

Conheça o inimigo antes de mapear a defesa. As 5 categorias que mais causam incidentes.

rede

Worms

Programas que se propagam automaticamente entre computadores explorando falhas de rede, sem precisar de interação do usuário.

Risco · alto
disfarce

Trojans

Disfarçam-se de softwares legítimos, mas transformam a máquina em um servidor acessível para invasores.

Risco · alto
sequestro

Ransomware

O temido sequestro de dados: criptografa arquivos e exige resgate em criptomoedas para liberar o acesso.

Risco · crítico
insider

Bomba Lógica

Código oculto que só dispara quando uma condição específica acontece — como a demissão de um programador.

Risco · médio
zumbi

Botnets

Dispositivos infectados controlados remotamente para ataques em massa — DDoS, mineração e spam.

Risco · médio

Defesa em camadas

Nenhuma medida isolada resolve. Combine antivírus, firewall, atualizações, MFA e backups para criar uma defesa resiliente.

// 04 — O elo mais frágil

Engenharia Social

Você sempre será o alvo mais fácil. Manipulação psicológica antes da exploração técnica.

Atenção: 95% dos incidentes de segurança começam com um clique humano.

Vishing

Golpistas usam chamadas telefônicas e técnicas de persuasão por voz para extrair dados e senhas.

voz · telefone

Smishing

Golpes via SMS que criam um falso senso de urgência para forçar um clique em links maliciosos.

SMS · mensagens

Phishing

Manipulação psicológica para roubar senhas e dados bancários através de e-mails e links falsos.

e-mail · links

Roubo de Identidade

O desfecho comum dessas manipulações: dados pessoais usados para fraudes e golpes financeiros.

fraude · financeiro
// 05 — Conformidade

Proteção de Dados & LGPD no ambiente corporativo

Privacidade não é checkbox — é arquitetura. Construa sistemas que respeitam dados por padrão.

01

O Desafio do BYOD

O uso de equipamentos pessoais no trabalho remoto dificulta o controle de segurança e expande a superfície de ataque das organizações.

  • Segmentação de redes
  • MDM e políticas corporativas
  • Zero Trust para endpoints
02

Privacy by Design

A privacidade deve ser incorporada à arquitetura do software desde as primeiras linhas de código — não como ajuste posterior.

  • Minimização de dados
  • Consentimento granular
  • Criptografia end-to-end
03

Risco das IAs Generativas

Atenção aos vibe-coders: usar IA para gerar código rápido sem validar brechas críticas ou o tratamento adequado de dados sensíveis é um risco real.

  • Revisão humana obrigatória
  • Dados sensíveis fora de prompts
  • Validação com SAST
// 06 — Para desenvolvedores

Seu usuário seguro começa no seu código

Checklist não-negociável para quem leva segurança a sério.

~/seu-usuario-seguro — checklist.sh
  • ✓Nunca envie arquivos .env para repositórios públicos — adicione-os ao .gitignore.
  • ✓Limpe comentários de depuração (como // TODO ou console.log) antes do deploy.
  • ✓Use ferramentas de análise estática (SAST) no pipeline de build.
  • ✓Salve senhas com algoritmos de hashing fortes como BCrypt — nunca em texto puro.
  • ✓Adote HTTPS everywhere, HSTS e cookies Secure + HttpOnly.
  • ✓Valide toda entrada no servidor — SQL Injection e XSS não são bug, são decisão de arquitetura.
